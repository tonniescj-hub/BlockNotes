# 方块书房 0.2.1 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将阅读、批量摘录、笔记、WPS 导出连成顺畅的本地工作流。

**Architecture:** 延续 0.2.0 的 React/Tiptap、PDF.js、Mammoth、docx、SQLite；不增加依赖或数据库表。沿用领域事务与可靠保存，阅读与笔记以临时返回上下文连接。

**Tech Stack:** 既有 Electron / TypeScript / CommonJS / SQLite。

**Spec:** 用户本会话已批准 0.2.1 四项范围并明确直接开发；本文记录实施细节，不重新请求批准。保持 AGENTS.md 与项目计划的书房、备份和输入规则。

## 范围与选择

沿用讲台摘录侧栏加入多选，将同一本资料的选中摘录按原文顺序加入新建或已有笔记；已有笔记相同来源不重复追加。引用、心得和可读出处一起保存。新建双栏编辑器或新资料中心会扩大范围，故使用现有界面。

从阅读进入笔记可直接返回原阅读位置；从笔记查看出处可继续回到该笔记，保留本次会话中的笔记页码。切换前等待可靠保存。笔记底部直接提供 Word 导出，成功后可打开 WPS；出错不显示成功。

Word 采用一个固定 A4 中文版式；正文、标题、引用、段落间距、显式分页保持可读。出处使用真实章节名或页码，不暴露内部块 ID。图片与表格保留既有 Word 导入/原件能力，不扩大笔记编辑器支持的节点类型。

不做 OCR、旧 doc、实时同步、云账户、AI、游戏机制或额外模板选择器。

## Global Constraints

- 不覆盖既有暂存的 0.2.0 改动和 output/；本次差异使用未暂存 diff 审阅。
- 当前分支继续原地开发，不复制工作树；Git 身份缺失时不伪造作者或修改全局配置。
- 原件不修改，资料/笔记变更事务化且检查 revision；失败保留用户输入。
- 原版资源保持忽略，公共包排除素材。

## Review Focus

- 多选中有失效摘录、跨资料、回收区笔记或旧 revision：整个追加必须回滚。
- 重复点击追加、重复 ID：不重复插入正文或来源。
- 编辑时切换原文再返回：正文、页码、可靠保存不丢失。
- 长 Word、普通表格/图片、长 PDF：导入后原件和内容可用，恢复一致。
- 无目录或摘录已删除：仍能看笔记，来源降级明确，不凭空定位。
